# 三态 epistemic state:好 / 坏 / 未知

**日期**: 2026-09-27
**阶段**: leo 计划的阶段二 —— **把"未知"提升为正式状态**
**结论**: 11/11 判据通过(3 seeds)。三态不是让报告更好看, 是让 agent **在整体失败时能自救**。

---

## 一、要修的是什么

`advq == 0` 在两种完全不同的情况下出现:

| 情况 | 含义 | 应该报 |
|---|---|---|
| 证据充分, 真的没有显著差异 | 中性 | **好** |
| **奖励流为空, Φ 学不到东西** | **没有数据** | **未知** |

而旧代码是 `advq = 0 -> 不 < 0 -> 不淘汰 -> 当作健康`。于是**"我不知道"被系统性地读成"没问题"**。

实测指纹(harm 故障下整臂全灭时):

    Q_adv ≡ 0.0000   精确零(健康段是 +0.0173)
    starved = True   since_rew 一路涨
    -> 旧的读法: 健康。真相: 账压根没记。

**这不是精度问题, 是自欺。** 一旦系统在这里出错, 后面任何稠密信号都会被错误解释。

## 二、实现(`hibs_lnn/rr_agent.py`, 全部加性)

### 2.1 自欺门: `rr_starved()`

    starved  = 连续 rr_starve_steps 步没有拿到任何正奖励(默认 3×horizon)

Φ 从奖励流学。**奖励流为空时 Φ 恒为初值, 此时任何"不坏"的结论都是自欺。**

### 2.2 三态判定: `rr_epistemic(o)`

    未知  —— 奖励流为空 / 势函数未离开初值 / 证据量 < rr_min_launches
    坏    —— 证据充分, 且**上置信界 < 0**(显著更差)
    好    —— 证据充分, 且没有显著负向信号

与旧 `rr_broken` 的关键区别: **"未知"不是"好"。**

### 2.3 决策层(三态驱动)

| 状态 | 行为 |
|---|---|
| 好 | 正常 UCB 参与选择 |
| 坏 | 退休, 但以 `rr_forgive_p` 的概率被**重新检验** |
| 未知 | **以 `rr_unk_p` 概率优先探索**(补证据); **永不算坏** |
| (全局)奖励流为空 | **退回安全基元策略** |

最后一条是 leo 契约里的"回退到安全基元策略": 承认"现在什么都判不了",
而不是用没有证据的判断去指挥行为。

### 2.4 报告层: 当前状态与历史状态**分开**

```
当前判定(决策用):  state = good / bad / unknown
证据量          :  n / n_eff / advq_n / no_base
近期状态        :  advq / advq_se / advq_lo / advq_hi / rate / eff
历史状态(审计用):  reached / rate_life / retired_n / recovered_n
全局            :  states{good,bad,unknown} / starved / since_rew / starve_ever
```

`retired_n` / `recovered_n` 是"持续学习是否真的在发生"的直接证据 ——
一个 option 被判坏过几次、又恢复过几次, 不能被当前状态覆盖掉。

### 2.5 三态本身是一条消融轴

`rr_three_state` 默认 `False` = 旧行为**逐位不变**(回归 7/7 已验证)。
`True` 时启用: 缓存为空 → 退回基元层; 未知 → 有限度探索; 未知 → 永不算坏。

## 三、结果(3 seeds × 300 回合, 三场景)

### 3.1 判据: 11/11 通过

    ① 自欺门: 奖励流为空时从不报'好'                违约 0 处
    ② 三态使 agent 在失败场景下恢复                  0.000 -> 0.567
    ③ 三态不增加误杀                                PASS
    ④ inert 场景下三态臂不误杀                       累计 0
    ⑤ normal 场景下目标 option 最终判'好'              PASS
    ⑥ 证据持续增长(normal / inert / harm)            三场景全过
    ⑦ 主任务不劣于 uniform                           11.24→11.22 / 11.16→11.17

### 3.2 最锋利的一组数

**harm 场景, `b2-nostate`(冻结基线但不启用三态):**

    段3-5  成功率 0.000   steps_go nan   usage 0.966   判定 unknown   starved True
           -> 整体死亡, 且**永不自救**

**harm 场景, `b2-3state`:**

    段3  成功率 0.633   T_adapt  83.7   判定 unknown   检测 43
    段4  成功率 0.633   T_adapt 106.3   判定 **bad**   检测  0
    段5  成功率 0.817   T_adapt  91.3   判定 **bad**   检测  2

差别不在报告, 在**行为**: 三态让 agent 认出"这个 option 没证据/是坏的",
停止依赖它, 主任务随之恢复。

### 3.3 一个副产品: 校准确实改善了 option 质量

同一个 regime 上, 目标 option 的 `advq`:

    uniform(随机选)      −0.27
    b2-*(校准选择)      ≈ +0.005 ~ +0.16

**这不是"option 有价值"的证据**(它们仍只是打平基线), 而是"校准把
无用的 option 挤掉了"的证据。注意 `good`/`bad` 是**相对基线 Φ** 判的,
所以 `≈0 -> good` 的含义是"不比基线差", 不是"比基线好"。

1. **稠密 cumulant** —— 阶段四, 见下。稀疏奖励是 Φ 冷启动的根因,
   但"哪个稠密量同时满足 ①在线 ②无 oracle ③与主任务相关"**还没有答案**。
2. **生存参数扫描** —— 阶段三, 表已列在 `docs/calib_baseline_freeze.md` §六。
   当前所有默认值(`rr_lr_v=0.2` / `rr_forgive_p=0.10` / `rr_unk_p=0.5` /
   `rr_starve_steps=3×horizon`)都**没有扫过**, 只知道能跑通。
3. **多 GVF(GVFBank 合并)** —— 阶段五。`hibs_lnn/knowledge.py` 的
   `InternalKnowledge` / `GVFBank` / `Coverage` / `Plasticity` 是现成入口,
   但**尚未与 RR 的三态证据合并**。
4. **知识增长的可测定义** —— 阶段六。
5. **只跑了 KeyDoor(纯 CPU)** —— 阶段七的硬门槛尚未全部满足前不进 LM4。

三类候选 cumulant 与四个共同判定, 按 leo 的框架:

| 类别 | 候选 | 风险 |
|---|---|---|
| A 转移/动力学 | 状态预测误差、转移不确定性、是否进入已知动力学区 | 可能只量"熟悉度", 不量任务进展 |
| B 结构进展 | 是否接近已学习目标区、是否减少不确定性、是否形成可复用转移链 | 可能把"更容易预测"误认为"更有用" |
| C 主任务代理 | 前置条件达成、关键状态转移、阶段性子目标完成 | 容易偷偷引入 oracle, 必须严格审计来源 |

四判: 正常时符号与 oracle 一致 / inert 时接近零不被误杀 /
harm 时仍产生负向证据 / 换 regime 后仍工作。
**评价重点是三态能否正确分离, 不是 cumulant 的预测误差最低。**
