# 在线可用的势函数 —— 是什么、为什么之前不行、边界在哪

**日期**: 2026-09-27
**问题**: "在线可用的势函数怎么解决?"
**一句话答案**: 用 **GVF**(中性初始化 + 每步 TD + 不用模型)替代"动作价值表取最大";
但它有**一条必须承认的边界** —— 势函数从奖励流学,而 agent 失败时奖励流是空的。

---

## 一、为什么"势函数"这个抽象一开始就是错的

原来的做法:

    adv = [Φ(s_end) − Φ(s_start)] / steps

三个问题,第三个是致命的:

1. 它把两件事混在一起:"option 把我移动了" vs "我还在学习,所以 Φ 自己变了"。
2. 乐观初始化下,`Φ(s_start) = Φ(s_end) = 常数` -> 恒等于 0。
3. **它需要 Φ,而 Φ 是要学的 —— 于是问题变成"怎么学一个足够好的 Φ",
   而不是"怎么判断 option 好坏"。方向被带偏了。**

正确的量是 **advantage**:

    A(s, o) = Q_opt(s, o) − Φ(s)

它直接回答"从 s 执行这个 option,比基线好多少" —— 这正是"要不要留它"该问的问题。
阈值 0 在**同一尺度**上有意义,而且早期 `A ≡ 0` = "还没有信息"(正确行为)。

Q_opt 由 SMDP 更新学出来,不需要任何 oracle:

    Q_opt[s0, o] += lr · [r_opt + γ^k · Φ(s1) − Q_opt[s0, o]]

**判别器从数学里自己掉出来**(不是手设计的阈值):

    inert(上限压到 1 步, 但那 1 步是好的): Q_opt ≈ γ·Φ(s1), Φ(s1) ≈ Φ(s0)/γ -> A ≈ 0  -> 不淘汰 ✓
    harm (反转 π_o, 朝反方向走):           Φ(s1) << Φ(s0)                        -> A << 0  -> 淘汰   ✓

## 二、Φ 该用什么 —— 三层实测

### 2.1 `Φ = max_a Q[s,a]`(agent 自己的动作价值表取最大)—— **不可用**

探针直接量出(444 次结算,健康 regime):

    V(s0) = 1.0000     ← **逐位等于初始化值**
    V(s1) = 0.9510     = γ·1.0
    γ^k·V(s1) = 0.717,  Q_adv = −0.275   ← 纯初值 artifact

根因不是"学得慢",是**结构性的**: 该表是**乐观初始化**(`q_init=+1.0`),
**只要某个动作还没试过,`max_a` 就还是 1.0**。
(32 个状态里 14 个有任一 Q 离开初值,但"最大值"几乎全停在初值上。)

而且还有第二层: **option 机制绕过了 Q** —— agent 靠模型导出的 π_o 导航,
基元动作只在 fallback 时用,所以 option 的启动状态上 Q 本来就不常更新。
**势函数恰恰在最需要它的地方是没学过的。**

### 2.2 `Φ = V_main`(模型 VI 的值迭代)—— 干净,但**是 oracle**

只能当"信号质量"的对照,不能当在线方案。

### 2.3 ★ `Φ = GVF` —— **答案**

一张**中性初始化(全 0)**的状态价值表,用 TD(0) 从 agent **自己走的每一步**学,
**不管那一步是基元动作还是 option 内部的动作**:

    Φ[s] += lr_v · [r + γ·Φ[s'] − Φ[s]]

为什么这样就成了:

| 性质 | 为什么关键 |
|---|---|
| **中性初值(全 0)** | 没有"未试过的动作把 max 顶在初值"这个病 |
| **奖励稀疏(+1 只在终点)** | `Φ(s)` 自然收敛成 γ^(到目标的步数) —— **正是**我们要的"离目标多远" |
| **每个转移都喂** | option 绕过 Q 也没关系:喂它的是真实转移,不是动作选择 |
| **不用转移模型/目标坐标** | **无 oracle** |

同一 regime、同样 300 回合,三种 Φ 直接对比:

    来源        Φ 范围              不同值    advq(door/key)        no_base
    learned     0.8515 ~ 1.0000       7      −0.2753 / −0.1387     0 / 0    ← 初值 artifact
    exact       0.0000 ~ 1.0000      13      +0.0075 / +0.0093     0 / 0    ← oracle 对照
    gvf         0.0000 ~ 0.9994      15      +0.0495 / +0.0356     9 / 3    ← ★ 符号与 oracle 一致

## 三、★ 两条边界的实测(比机制本身更重要)

### 3.1 退休会**切断证据来源**,所以任何判据都会自我封闭

`advq` 判据第一版(均值 < 0)在链上把 option 全判坏:

    Q_adv = −0.0059(常数), fallback 占比 0.991   ← 99.1% 的选择返回"没有可用 option"
    两类故障输出**逐位相同**                      ← option 几乎不执行, 故障无从生效

**机制**: 判坏 -> 不再使用 -> 统计量冻结 -> 永远坏。**判据本身无法自救。**

改法不是调阈值,是加一条**通路**: `rr_forgive_p` —— 被判坏的 option
以 p 的概率被**重新检验**。

    advqGVF-forgive:  fallback 0.991 -> 0.397(inert) / 0.276(harm)

**「犯错是可以原谅的」在机制上就等于「退休可逆」。** 没有这条路,
任何判据的第一次误判都是永久损失。

另一条: 判据从"均值 < 0"改成"**上置信界 < 0**"(显著更差)。
实测量到 `Q_adv = −0.0002` —— 那是**零的噪声之内**,严格 `< 0` 会误杀。
这个改法不需要任何手工 ε: 尺度由数据自己的方差给出。

### 3.2 ⚠ GVF 的冷启动边界: **agent 失败时奖励流是空的**

`harm` 故障下:

    T_adapt = 300(打满), 步数 = nan, 成功率 0     ← 整个臂全灭
    Q_adv ≡ **0.0000**(精确零, 健康段是 +0.0173)  ← 不是"没变化", 是"账压根没记"
    检测延迟: 未检测

因果链: harm 把 π_o 反转 -> agent 到不了终点 -> **奖励流为空** ->
`Φ` 学不到东西,恒为 0 -> `_rr_has_base` 挡掉全部证据 ->
**判据永远开不了火**。

**势函数从奖励流学;agent 失败时奖励流为空 —— 信号在它最该起作用的时候不可用。**

这不是接线 bug,是 **GVF 作为势函数的固有前提**: 它是**预测**,
预测需要被预测的事件发生。而"agent 正在失败"恰恰意味着"成功事件没发生"。

**两个方向(未做,明写)**:

1. **换稠密的基本量(cumulant)。** 稀疏奖励(+1 只在终点)是根因。
   OaK 的每个组件都是 GVF,基本量不一定是主奖励 —— 用**稠密的**观测量
   (仓库里 `rl_proposer.py` 的 `(c, z)` GVF 层就是为这个设计的,
   `V_θ(s,a) = θ·φ(s,a)`)。但"哪个稠密量同时满足①在线 ②无 oracle
   ③与主任务相关"**还没有答案**,需要单独一轮。
2. **至少别把"没证据"报成"没问题"。** 现在 `advq = 0` 会被读成"不坏",
   真相是"不知道"。`bad_q` 已经要求 `advq_n >= min_launches`(证据不足不判坏),
   但**报告层没有三态** —— 必须把 "好 / 坏 / 未知" 分开报。
   这是本轮**没做完**的一件事。

## 五、结论

1. **"在线可用势函数"的答案是 GVF**,不是"更好的 Φ 公式":
   中性初始化 + 每步 TD + 不用模型。实测符号与 oracle 对照一致。
2. **但它有一条边界**: 势函数是预测,预测需要事件发生。
   agent 失败 -> 无奖励 -> 无势函数 -> 无法校准。
   **要么换稠密基本量,要么把这个盲区明确报成"未知"。**
3. **退休必须可逆**,否则判据自我封闭。这不是优化,是判据能成立的前提。
4. 阈值必须是**显著更差**(上置信界 < 0),不是"不等于零" ——
   实测 `Q_adv = −0.0002` 落在噪声内。

**仍然没做**: 稠密基本量的选型;报告层三态(好/坏/未知);
`rr_lr_v` / `rr_forgive_p` 未扫;只在 KeyDoor 验证。
