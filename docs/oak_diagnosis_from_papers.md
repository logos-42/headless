# 用 OaK 原始文献诊断本项目 —— 为什么「Options 有害」

> 读的文献
> - Sutton, Bowling, Pilarski, **The Alberta Plan for AI Research**, arXiv **2208.11173**(OaK 的原始出处)
> - Sutton, Machado, Holland, Szepesvari, Timbers, Tanner, White,
>   **Reward-Respecting Subtasks for Model-Based Reinforcement Learning**, arXiv **2202.03466**
> - 旁证:Kulkarni et al., h-DQN, arXiv 1604.06057

**一句话结论**:

> 「Options 有害」不是关于 option 的结论,而是关于
> **① 我只实现了论文实测最差的那一类 option、② 我用了一个在原理上测不到该机制收益的度量、
> ③ 我在一个没有可被抽象结构的基准上评估它** —— 这三件事的结论。

---

## 1. 最硬的一条:STOMP 走反了

**Alberta Plan Step 10 原文**:

> "The highest ranked features are made each into a separate reward-respecting subtask …
> Each subtask is solved to produce an option. For each such option, its model is
> **learned and added to the transition model** used for planning. This progression —
> **SubTask, Option, Model, and Planning** — is called the STOMP progression."

```
OaK:   SubTask ──> Option ──> Model ──> Planning      (model 是 option 的**产物**)
本项目: 转移图(Model) ──> 路径/bottleneck ──> Option   (model 被当成 option 的**来源**)
```

**我完全跳过了 SubTask 层,并且把 model 的角色搞反了。**

**论文对这条的动机说得很直白**(2202.03466 摘要):

> "the space of possible options is immense, and the methods previously proposed for option
> discovery **do not take into account how the option models will be used in planning**"

---

## 2. 我实现的正是论文点名的最差类别

**2202.03466 摘要原文**:

> "option models obtained from such reward-respecting subtasks are **much more likely to be
> useful in planning than eigenoptions, shortest path options based on bottleneck states**,
> or reward-respecting options generated by the option-critic."

我的 `OptionManager.discover_subgoals()` 用 **介数中心性找 bottleneck 状态**当作子目标 `g_o`
—— 这**逐字对应**论文点名的 `shortest path options based on bottleneck states`。

而论文 Figure 1(两房间 gridworld)的实测结果是:

> "Planning with the shortest-path option was actually **slower** by this measure than
> planning with actions alone."

**→ 我测出「option 让性能下降」与文献一致。但我测的正是文献证明最差的那一类。**

---

## 3. option 的正确形式里没有「目标」

**论文原文**:

> "an option is a pair, `o = (π_o, β_o)`, consisting of a **policy** and a **stopping function**.
> Actions are a special case of options in which the policy always selects the action and the
> stopping function always stops."

脚注 2 更直接:

> "Options as originally formulated also specified a set of states in which they could be
> initiated. **We don't use that in this work so we elide it** for simplicity."

**所以:**
```
论文:  o = (π_o, β_o)               目标不在 option 里, 在 subtask 里
本项目: o = (I_o, g_o, π_o, β_o)    我把 subtask 的职责压进了 option
```

**目标在 subtask 里是以 stopping value `z` 的形式出现的**(2202.03466 §2, 式 4):

```
第 i 个 subtask 的停止价值:   z_i(s) = wᵀx(s) − w̄_i·x_i(s) + w̄_i·x_i(s)
停止奖励 (stopping bonus):    (w̄_i − w_i)·x_i(s)
```

含义:**「在特征 x_i 高、且整体价值也高的状态停止」**。停在一个高价值状态才给奖励 ——
`z` 不是"到达某个坐标",而是"停在该停的地方"。

**→ 我的 `g_o`(一个状态向量 + 欧氏距离)是把 subtask 的职责错误地压进了 option,而且丢掉了"停止奖励"这个关键机制。**

---

## 4. 缺整整一个 subtask 层(GVF 的 c 与 z)

**论文原文**:

> "different option-discovery methods differ **only in how they define the GVFs' cumulants
> and stopping values**"

**这一句把整个 option 发现问题归结成两件事:选 `c`(cumulant)和选 `z`(stopping value)。**

我的项目里有一个 `GVFBank`(Horde/TD(λ)),**但它与 option 发现完全没有接线** ——
`OptionManager` 从来不看它。

**论文给出的四种方法的差别,全在 `(c, z)` 上:**

| 方法 | cumulant `c` | stopping value `z` |
|:--|:--|:--|
| 主任务 | `R_t` | 不允许停止 |
| shortest-path(bottleneck) | `−1` | 子目标处 0,否则 −∞ |
| eigenoptions | 图 Laplacian 特征向量的差分 | 0 |
| **reward-respecting(推荐)** | **`R_t`(与主任务相同)** | **基于 `v_π`,带 bonus 权重 `w̄_i`** |

**我实现的是第二行(最差),完全没有实现第四行。**

---

## 5. option 没有价值函数,也没有 off-policy 学习

**论文 §3**:

> "we specify the **off-policy** learning algorithms we use to approximate the optimal value
> functions and optimal options"
> "To **solve** the subtask is to find an option which maximizes (2)."

解 subtask = 用 actor-critic + UWT(带 eligibility trace 的通用 TD 更新)从 off-policy 经验
**学出** `π_o` 和它的价值函数。

**我的 `π_o` 是对转移模型的一次贪心 argmax:**
```
a = argmax_a [ ‖g−s‖ − ‖g−T(s,a)‖ ]        # 我实现的
```
**这不是学出来的策略,每个 option 也没有自己的价值函数。**
形式上它是一个"模型驱动的单步爬山",没有 credit assignment,没有 off-policy 修正。

---

## 6. ★ 机制的核心用途整个缺失:option model 不参与 planning

**论文把 option 的用处说得很清楚**:

> "The appeal of options is that they are in some ways interchangeable with actions.
> Just as we can learn models of action's consequences and **plan with those models**, so we
> can learn and **plan with models of options' effects**."

**option 的价值 = 让 planning 更高效(减少 look-ahead 操作数)。**

我的实现里 option 只被用于**动作选择**(替换 base policy 的输出),
**没有任何 planner 消费 option model。**

**→ 按构造,我实现的这套东西不可能体现出 option 的收益。** 论文 Figure 1 的整个实验,
横轴就是"planning look-ahead operations",我连这个量都没测。

---

## 7. 度量选错了(第 6 条的直接后果)

| | 论文 | 本项目 |
|:--|:--|:--|
| 主指标 | **planning efficiency** —— 达到 `v*(s0)` 所需 look-ahead 操作数 | base learner 的 any-time accuracy / `T_adapt` |
| 对照 | 与 primitive actions 的模型做 planning 对比 | 与无 option 的 base policy 对比 |
| 机制触发证据 | option 被 planner 选中 | `option_steps` / `replan_steps` |

**我在测一个这个机制在原理上不会改善的量。** 这正好接上本轮自己写的判据:
**「机制的价值通常不体现在稳态性能上」** —— 论文给的是它的正确落点。

## 8. 缺 OaK 第 11 步:utility feedback 与**删除**

**Alberta Plan Step 11 原文**:

> "The Oak architecture modifies Prototype-AI II by adding feedback processes that continually
> assess the **utility of all the elements** (features, subtasks, options, and option models)
> and determine **which elements should be removed and replaced with new elements**.
> For example, **if an option model is never useful in planning, then it and the corresponding
> option and subtask should eventually be deleted**."

我明确决定了「**Option 不删**」。
**而 OaK 与 Prototype-AI II 的唯一区别就是这套删改反馈。** 去掉它,做的就不是 OaK。

## 9. 跳过了前置步骤

```
Step 8   Prototype-AI I   one-step model-based RL —— **没有** temporal abstraction
Step 10  Prototype-AI II  加入 subtask + temporal abstraction (STOMP)
Step 11  OaK              加入 utility feedback / 删改
```

论文对 Step 8 的定位:

> "Prototype-AI 1 would be an integrated architecture with **everything except temporal
> abstraction (options)**. Without temporal abstraction Prototype-AI 1 will be weak and
> limited in many ways"

**我在没有一个可信 planner 的情况下直接做了第 10 步。** 而 Step 8 的组件清单里
(递归状态更新 / 一步模型 / feature finding / feature 排名 / search control)
我只有"一步模型"。

## 10. `max_opt_len = 3` 把时间抽象掐死了

论文的 option 在两房间 gridworld 里跑到 **11–17 步**(直到 `β_o` 触发)。
我硬封顶 `_opt_max_age = max_opt_len = 3` —— **比很多 primitive 轨迹还短**。

**"时间抽象"一旦短于原有时间尺度,它在形式上就不构成抽象。**

---

## 11. 为什么在 lm4 上必然测不出(`A ≡ 0` 的再解释)

论文里 option 的收益来源是两个:
1. **绕开负奖励区域**(reward-respecting 的 option 走"绕路"而不是最短路径)
2. **到高价值状态**(stopping bonus 的前提:停在"特征高**且**价值高"的状态)

**两者都需要状态空间有可被绕开的区域、有瓶颈、有价值的梯度。**

lm4 的实测:`I(a,b)` 纯迁移 = **0.0000**、不对称性 `A ≡ 0.0000`(CI `[0,0]`)、
唯一的动力学是**对称的纯干扰** → 没有可绕开的区域、没有瓶颈、没有顺序依赖。

**→ 在这个基准上,任何类别的 option 都不可能有收益,与实现好坏无关。**
这正是本项目自己写下的判据(`docs/option_benchmark_problem.md`)与文献的独立吻合。

## 12. 结论与重做优先级

### 结论

```
那次「Options 显著有害」是三重复合的产物:
  A. 只实现了论文实测最差的一类 option (bottleneck/shortest-path)
  B. 缺 subtask 层 (GVF 的 c/z)、option 无价值函数、无 off-policy 学习
  C. 度量选了测不到该机制收益的量 (稳态性能而非 planning efficiency)
  D. 基准本身无时序结构 (A ≡ 0)
  E. 外加真 bug (发现管线两处 + coverage 从未写入)
```

**没有一条是关于「option 有没有价值」的。**

### 重做优先级(按论文顺序,不跳步)

```
P0  在论文的 four-room gridworld 上**复现文献的两个已知结果**:
      ① shortest-path/bottleneck option 的 planning 比 primitive 还慢
      ② reward-respecting option 的 planning 明显更快
    这是一个有明确正反例、可完全复现的对照 —— 项目唯一的 ground truth。

P1  补 subtask 层:定义 GVF (c, z),按 w_i 排名选 subtask (reward-respecting),
    用 stopping bonus  (w̄_i − w_i)·x_i(s)

P2  补 option model + planner:option model 进 planner,
    指标换成 **planning look-ahead operations**

P3  option 用 off-policy actor-critic 学(复用已有的 UWT/IDBD 线),
    `β_o` 学出来,`max_opt_len` 由 `β_o` 决定而不是硬封顶

P4  加 utility feedback:记录每个 option 在 planning 里被选中的次数,
    长期为 0 的 option + subtask 一起删除并替换

P5  再回到 lm4/lm5 —— 前提是先给它们造出**有价值结构**的状态空间,
    否则它们永远测不了时间抽象
```

**P0 是本轮之后第一步:** 它不需要 actuator、不需要 GPU 集群,
在纯表格 gridworld 上就能跑,而且能一次性验证"我的 planner + option model 管线是否正确"。
