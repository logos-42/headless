# 发现:`--stream` 对 oak 路径是死参数,实际任务流退化为「单域」

**日期**: 2026-09-29
**严重性**: **高 —— 影响 L2/L3/L4 全部 `--proposer oak` 批次的解释口径**
**发现方式**: L5 事前注册的独立设置选的是 `--stream nonstationary`,启动后按
「处理变量必须回读确认」(不是假设它生效)去日志里找 `[stream]` 行,**发现它不存在**。

---

## 1. 代码事实(逐行核实)

`tests/run_lm4_wave.py`:

| 位置 | 内容 |
|:--|:--|
| `:1188` | `ap.add_argument("--stream", default="fixed", ...)` —— CLI 里有这个开关 |
| `:666` | `if proposer == "bins":` ← **整段 stream 逻辑的宿主** |
| `:672-704` | `_explicit` / `fixed` / `perm` / `revisit` / `nonstationary` 五种调度,**全在这个 `if` 里面** |
| `:706` | `print("[stream] %s -> 粗域序列 %s" ...)` ← 同在这个 `if` 里 |
| `:1052` | `"stream": stream,` ← **只是把标志值记进 JSON,不是"用过"的证据** |
| `:815` | `for step in range(n_rounds):` ← 训练主循环 |
| `:821` | `dd = domains[step] if step < len(domains) else domains[-1]` ← **无条件执行** |

⇒ 当 `--proposer oak`(L2/L3/L4/L5 全部)时,`:666` 分支不进,**`:821` 就是唯一的域选择逻辑**:

```
step 0..5    → domains[0..5]   (每个域各一次)
step 6..299  → domains[-1]     (永远最后一个域)
```

`--stream` 的任何取值在此路径下**完全不产生作用**。

## 2. 实测证据(不是推断)

### 2.1 日志里没有 `[stream]` 行

    grep "\[stream\]" results/oak_longv5.log   → 空
    grep "\[stream\]" results/oak_longv4.log   → 空      (L4 也一样)
    grep "\[shift\]"  results/oak_longv4.log   → 无该项, 因为 shift 未启用

### 2.2 域分布(数 L4 一个 run 的 300 步)

    grep -o "step[0-9]* (域[0-9]*)" results/oak_longv4.log | tail -300
    → 域5: 295 次 | 域0: 1 | 域1: 1 | 域2: 1 | 域3: 1 | 域4: 1

### 2.3 acc_matrix 的形状也吻合

`results/oakL4_e9_s2`,300 × 6:

| 时刻 | D0 | D1 | D2 | D3 | D4 | D5 |
|:--|--:|--:|--:|--:|--:|--:|
| 第 6 行(刚走完一轮) | 0.805 | 0.403 | 0.801 | 0.201 | 0.952 | **0.000** |
| 末行(第 300 步) | 0.644 | 0.837 | 0.402 | 0.982 | 0.597 | **0.953** |

D5 从 0.000 → 0.953,因为它被训练了 295 轮;其余域被训练 1 轮后基本靠回放维持。

## 3. 这意味着什么

1. **L3/L4 的"任务流"不是持续学习序列,是「一遍 6 域 + 之后 294 轮单域精调」。**
   `final_mean_acc` 是"训练了 295 轮的 D5 + 只训练过 1 轮的 D0–D4"的平均,
   各域的**训练量极不对等**。
2. **`--stream` 这一族的结论从未被测过**: 批头里写的 `stream: revisit` 与事实不符。
3. **L4 的方差发现需要重新评估。** 方差降低可能是"D5 单域训练阶段的稳定性"
   而不是"持续学习中的稳定性"。**在有效任务流下重测之前,不能写进论文。**
4. **L2 的 `H2` 结论(O2 闭环 vs O1 开环)不受影响** —— 那是**同一条流下的臂间对比**,
   流是什么不改变"闭环优于开环"这个相对结论。但**绝对口径**(这些都是 CL 成绩)
   需要改写。
5. 好的一面:**option 层的相对比较仍成立**(同一流下比),而 `goal_reached 1→95`
   这个机制读数也与流无关。

## 4. 最小修复(尚未执行 —— 需用户决定)

把 `dom_seq` 的计算从 `:666` 的 `if proposer == "bins":` 里**提出来**,让它在所有
proposer 下都执行;并把 `:821` 改成 `dd = dom_seq[step]`。

改动量:约 20 行(`dom_seq` 的计算块整体外移 + 一行替换)。

### 4.1 为什么我没有直接改

- 用户明确指令:**「现在不要碰 LM4」**。改任务流会改变**所有既有 LM4 数字的含义**,
  属重大口径变更,不是顺手修的 bug。
- 改完之后,`fixed` 与 `revisit` 才各自成为真实的 CL 流;`nonstationary` 才有意义。
- 这需要用户确认**是否接受**"L2/L3/L4 的绝对口径需要重跑"这个代价。

### 4.2 修复后必须加的**回读闸门**

本次的教训是"标志值被记进 JSON"被误当成"生效"。修复后必须:

```
· 运行结束时打印**域直方图**(`Counter(dom_seq)`), 并写进 JSON
· 启动/验收时断言直方图的熵 > 0 且最大域占比 < 1.5 × (1/n_domains)
  - 退化流(域5 占 295/300 = 0.983)会被这条直接抓住
```

**只有"直方图"能证明流生效;`--stream` 的取值本身不能。**

## 5. 对 L5(方差复现)的影响

- 原定独立设置 `--stream nonstationary` **不成立**(死参数)。
- L5 已启动并在发现后**立即停止**:只有 1 个 run 刚起头,**未产生任何可用数据**。
- 事前注册的**判定规则**(H2/H2b/H3、F 检验 + 自助法、天花板否决)依然有效,
  **需要改的只是"独立设置"这一项**。规格里已留痕。
- 两条可选路径:
  - **A(需碰 LM4)**: 先修 `:821`,让 `--stream` 真正生效,再跑 L5。
    这同时修复了 benchmark,**L5 变成"在真实 revisit 流下复现"** ——
    这是最强的复现,但也意味着 L3/L4 的绝对口径要重跑。
  - **B(不碰 LM4)**: 换一个**已确认生效**的旋钮做独立设置。
    已核实在主循环里无条件生效的只有 `--shift-at` / `--shift-every`
    (`:816-820`,且有 `[shift]` 打印),以及 `--domains`(改域粒度)。
    但**在退化流上做复现,得到的仍是在退化流下的方差行为** —— 信息量低。

**我的建议是 A**,理由是它不是"顺手改 LM4",而是**修一个让 benchmark 名不副实的
接线错误**;不修的话,后面任何 CL 结论都建在"294/300 轮单域精调"上。
但这条要用户拍板,因为它改变了既有全部绝对数字的含义。
