## 0. 这份报告回答什么

之前项目的负结果(**所有 option 模式都不优于 primitive**)有两种可能读法:

- (a) option 这个机制在该任务上没有价值;
- (b) option 的**驱动层**错了 —— 一直从转移图(bottleneck / 介数中心性 /
  最短路)反推,而那正是论文点名的**最差类别**。

本报告把驱动层换成论文的 **SubTask**(reward-respecting 子任务),并补齐
**三个方向的对照**(负向 / 正向 / 随机目标),在**两个试验台**上给答案。

---

## 1. 层序(不可颠倒)

```
SubTask ──> Option ──> Option model ──> Planning
 (c, z)      (π_o,β_o)     SMDP model      planner
```

子任务 = 一个广义价值函数 `(c, z)`:

```
c(s,a) = R(s,a)                            ← 与主任务**相同**的奖励
z_i(s) = V_main(s) + (w̄_i − w_i)·x_i(s)     ← 只在 x_i(s)=1 处允许停
         └────────── stopping bonus ──────────┘
```

**`w_i` 是特征 i 在主任务价值函数里的权重, 不是常数 1。** 硬写 `w_i = 1`
会让 bonus 恒 0 → `z ≡ V_main` → `β_o` 处处为空 → option 永不停止 → 与
shortest-path 给出**逐位相同**的曲线。实测本任务 `w_key = 0.7804`,
`w_door = 0.7542`。

**option 执行必须是闭环**: `a_t = π_o(s_t)` 每步按当前状态重算, 不是固定
动作序列 replay。本项目此前 4 次同型失败都源于此。

## 2. 机制存活证据(先证明"它真的在跑", 再谈效果)

判据写在跑之前(`tests/test_rr_options.py` / `tests/test_rr_agent.py`)。

| 判据 | 结果 |

| `z ≢ V_main`(非退化) | ✓ `w_i=0.78/0.75 ≠ 1` |
| 闭环: recompute-count ≈ 执行步数 | ✓ `210 == 210`(open-loop 会是 **0**) |
| 终止原因台账非空且**不是超时兜底** | ✓ `{beta_at_feature: 43}`, `expired: 0` |

## 3. 试验台能力检验(不是所有台子都能回答)

| 试验台 | 有时序结构? | 有**代价区**?(负对照的前提) | 能回答什么 |
|---|---|---|---|
| lm4 | `A ≡ 0`(动作可交换) | — | ❌ 什么都回答不了 |
| KeyDoor | `A ∈ [−1,+1]`, 33% 显著 | ❌ **无代价区** | 正向、剂量;❌ 负向 |
| 论文 gridworld | ✓ | ✓ 走廊 + 绕行 | 正负双向 + 随机对照 |

论文的负向结果依赖**两个前提同时成立**:「最短路**穿过**代价区」**且**
「存在**绕行**」(`option-design-and-execution.md` §9.2)。KeyDoor 只是
一条直线, 任何"往右的宏动作"都有用 —— 所以**瓶颈臂在 KeyDoor 上必然
不产生论文的负向**, 这不是 bug, 是台子不具备那个结构。

## 4. 实验一: 规划指标(论文自己的尺子, look-ahead 操作数)

`tests/benchmark_rr_planning.py`。指标 = 价值迭代收敛到 `|V(s0)−V*| < 0.01`
所需操作数。**这是论文用来衡量该机制的指标。**

```
regime A (key=2 door=5 goal=7)     ops   ×primitive   mean_k
  primitive                       1080      1.000       1.00
  rr-exact                         540      0.500       1.94
  rr-zeroV                         180      0.167       5.80
  rr-nobonus                       540      0.500       2.16
  rr-nocum                         540      0.500       2.03
  rr-nofeat                       1200      1.111       1.75
  bottleneck                      1350      1.250       3.88
  random                           180      0.167       4.03

四 regime 的 ×primitive:
  rr-exact     0.500  0.667  0.333  0.500    ← 四段全 ≤ 1
  bottleneck   1.250  1.250  1.250  1.250    ← 四段全 > 1
  rr-nofeat    1.111  0.972  1.250  1.250
```

**① 瓶颈臂 1.250× —— 逐位命中论文的 2145/1716 = 1.25。** 负向复现。

**② 但 `rr-zeroV` / `random` 反而比 `rr-exact` 更省。** 加 `mean_k` 仪表
后原因清楚: `ops` 与 **option 时长**强相关(`k=5.8 → 180 ops`,
`k=1.94 → 540 ops`)。一个 k 步的 option 只花 1 次 backup 就传播 k 步的
价值 —— **在这个指标上, "更长" 与 "更准" 不可分。**

⇒ 因此**规划指标不能用来支持"目标选得好"这个claim**。它只能支持:
rr 有效(≤ primitive)且瓶颈有害(> primitive)。

### 5.1 ⚠ T_adapt 在此试验台上**饱和**

`t_adapt` 的下限 = 滑动窗口长度 = **20**。所有 option 臂都贴在地板
(20±0), 连**瓶颈臂**也是 —— 于是 T_adapt 在 6 段里 5 段**看不见任何
臂间差别**。

按事前写死的判据 ②「bottleneck 优于 primitive ⇒ harness 有 bug」: **没有
bug**, 而是 KeyDoor 没有代价区(§3), 瓶颈宏动作(均 2.36 步向右)在这里
天然有益。

**⇒ 在这台子上, T_adapt 不能作主指标。** 项目此前所有以 T_adapt 为
头条的 option 结论都受这一条污染。

### 5.2 会动的尺子: 成功回合平均步数

按指标饱和时必须换 metric 的规则改为 **steps-to-goal**:

```
相对 primitive 的逐段步数优势 (正 = 步数更少):
  rr-exact    +1.7 +2.1 +1.6 +1.3 +2.0 +1.7   ← 六段全胜
  rr-zeroV    +2.0 +2.7 +1.8 +1.7 +2.5 +1.8   ← 最好
  rr-learned  +2.0 +2.7 +1.8 +1.7 +2.5 +1.8
  rr-nocum    +1.7 +2.1 +1.6 +1.3 +2.0 +1.7
  bottleneck  +0.2 +1.9 +0.8 +1.4 +2.5 +1.6   ← 明显不如 rr
  random      +2.0 +0.9 +1.8 +1.7 +2.7 +0.8
```

**① option 有效**: 每个 option 臂在六段上都优于 primitive。
**② 但瓶颈臂也接近 rr**(差 0.5~1.0 步)—— 再次印证 §3: 台子分不开。

### 5.3 价值函数假设(用户猜测)的**直接检验**

用户猜测「可能是价值函数的原因」。本矩阵给**反向**答案:

```
rr-exact   (z 用 V_main)   → 9.4 14.7 9.2 9.3 14.7 9.2
rr-zeroV   (z 不用 V_main) → 9.0 14.2 9.0 9.0 14.2 9.0     ← 更好
rr-learned (z 用 agent 的 Q) → 9.0 14.2 9.0 9.0 14.2 9.0   ← 同样更好
```

**去掉价值函数反而更好。** 机制上说得通: `V_main` 让 `β_o` 提前触发
(`|β|=33` vs `zeroV` 的 `|β|=4`, 平均时长 5.65 vs 7.83 步), 提前把控制权
还给**尚未训练好的** base policy。学习早期 base policy 差, "早点交还"
就是把好局丢掉。

**措辞纪律**: 这是 KeyDoor 上的观测, 不能推广成"价值函数在任何地方都
有害"。它是对**在线、模型无关、base policy 还在学**这个组合的观测。

### 5.4 剂量响应 + 内部哨兵(`tests/bench_rr_sentinel.py`)

| 剂量 `opt_prob` | ΔT |Δ\|均 | ΔS |Δ\|均 |
|---|---|---|---|
| 0.00 | 0.0 | **0.00** |
| 0.25 | 40.4 | 0.81 |
| 0.50 | 41.4 | 0.73 |
| 1.00 | 40.5 | **1.79** |

- **哨兵 ✓**: `opt_prob=0` 与 `primitive` 对照臂 **T 与 S 都逐位相同**。
  诊断自身正确, 剂量点可解读。
- ΔT 对剂量平坦(因为饱和), **ΔS 随剂量单调**(0.25→0.81→0.73→1.79,
  末点显著)—— 收益与"机制被允许动作的程度"同向。

## 6. 实验三: 三个方向在论文自己的 gridworld 上

`tests/benchmark_oak_repro.py`(本轮**新增条件 D: 随机目标**)。

```
                     primitive   shortest-path   rr(最佳)   随机目标(20次)
两房间(确定性)          1400        1750 (1.250)   875 (0.625)  中位 0.500 ✗
四房间(随机, slip=2/3)  48872       53710 (1.099)  26200(0.536) 中位 0.828 ✓
```

| 方向 | 两房间 | 四房间 |
|---|---|---|
| ① 已知负向: shortest-path **不更快** | ✓ 1.250 | ✓ 1.099 |
| ② 已知正向: reward-respecting **明显更快** | ✓ 0.625 | ✓ 0.536 |
| ③ 随机对照: rr **优于随机目标中位数** | **✗** (0.625 vs 0.500) | **✓** (0.536 vs 0.828) |

**诚实读法**:

- ①② 在**两个布局上都复现** —— `SubTask → Option → Option model →
  Planning` 这条管线是对的。这是 harness 的双向校准(§9)。
- ③ **只在四房间成立**。两房间只是"一条走廊 + 一个门", 绝大多数随机目标
  仍然**跨过了走廊**, 而跨走廊正是这个任务的**全部内容** —— 所以随机目标
  与 rr 等价。**两房间这个试验台不具备分开"目标质量"的结构。**
- 四房间有真结构(多个房间 + 真实绕行), 典型随机目标跨不了有用的子路径,
  此时 rr 显著优于随机。**随机臂的分布极度右偏**: 20 次抽样里最好的两个
  (0.027 / 0.028)比 rr 还快, 但中位数 0.828 —— 即"抽到一个恰好跨走廊的
  目标"是少数事件, 典型随机目标是**没用的**。这也是为什么主判据必须用
  中位数: 用均值(0.646)会把"运气"记成"随机目标也行"。

**结论措辞**: 在**结构足够复杂**的环境里, "目标选得好"确实是收益来源
(四房间); 在结构简单的环境里, 收益可以完全由"有 option"解释(两房间)。
**不得**写"目标质量是关键"这种无条件说法。

## 8. 结论(逐条可核验)

1. **OaK 的第一步(SubTask → Option)已实现并验证机制存活**: `β_o` 非空、
   闭环执行、无 lock-in、对照逐位干净。
2. **论文的负向(瓶颈 option 无效甚至有害)在**两个** gridworld 布局上复现**
   (1.250 / 1.099), 且 KeyDoor 规划指标上也是 1.250×。
3. **论文的正向(reward-respecting 更快)在两个布局上复现**(0.625 / 0.536)。
4. **"目标选得好"只在四房间成立** —— 两房间这个台子分不开。写报告必须
   带上"试验台是否具备该结构"这一限定。
5. **价值函数在在线场景下反而有害**(rr-exact 9.4 步 vs rr-zeroV 9.0 步),
   机制解释是 `V_main` 让 `β_o` 提前触发、把控制权过早交还给未训练好的
   base policy。**这是对"价值函数是收益来源"这个猜测的反向证据。**
6. **KeyDoor 的 T_adapt 饱和**(所有 option 臂贴 20 地板), 不能作主指标;
   steps-to-goal 是这台子上会动的尺子。项目此前以 T_adapt 为头条的
   option 结论全部受此污染。

## 9. 未做的事(明写, 不当已做)

- **KeyDoor 上没有有效的负对照**(无代价区)。要在这台子上做负向, 必须先
  给它加一个**代价区 + 绕行**(§3 的两个前提), 否则任何负向结论都是
  台子的性质而非机制的性质。
- **`rr-nobonus` / `rr-nocum` 在 KeyDoor 上与 `rr-exact` 行为等效**
  (输入不同、台账相同 —— 已用代数检查确认为真等效, 非共享分支)。它们
  只在规划指标的 regime D 上分开(nocum 1.500 vs exact 0.500)。
- **`rr-learned`(无 oracle)与 `rr-zeroV` 在在线场景中重合**, 因为
  agent 的 Q 在乐观初始化下接近常数。需要更长的预热才能分开。
- **Option model → Planning 层尚未在 KeyDoor 的在线回路里用起来**
  (在线臂只用 option 执行, 没用它的 SMDP model 做规划)。论文的收益
  主要在规划侧。
- 服务器 L3 批(旧判据)与本报告的 L3 后续未对读。
