## 一、机制(`hibs_lnn/rr_agent.py`,全部加性)

| 旋钮 | 含义 |
|---|---|
| `rr_persist` | 台账是否跨 regime 存活(False = 每次库重建清零) |
| `rr_forget_hl` | **忘记半衰期**(以启动次数计)。`inf` = 终身平均 |
| `rr_pot` | 势函数来源:`learned` = agent 自己的 `max_a Q`(无 oracle)/ `exact` = 模型 VI |
| `rr_retire_rule` | 淘汰判据:`internal`(旧) / `adv` / `both` / `either` |
| `rr_score` | 选择分数:`rate` / `eff` / `adv` |

实现要点:所有有效计数按 `decay = 0.5^(1/hl)` 指数衰减,`hl=inf → decay=1.0`
→ 逐位复现旧行为(哨兵与 7/7 自检**逐位不变**,已验)。

## 二、为什么"持久化必须配遗忘"——否则持久化是有害的

链 A B C A B C,段 4 起把 `rr[door]` 弄坏。看 `终身率` vs `当前率`:

| 遗忘半衰期 | 终身达成率(旧账) | 当前胜任度(真相) | 检测延迟 |
|---|---|---|---|
| `inf`(不遗忘) | 0.500 | 0.500 | **1201** |
| 200 | 0.844 | 0.499 | 291 |
| 50 | 0.953 | 0.494 | 79 |
| 20 | **0.981** | 0.489 | **31** |

> **旧账说「这个 option 达成率 98.1%,几乎完美」,而真相是 48.9%,已经坏了。**

不遗忘 → `n` 跨 regime 累积到几百 →(a) 历史成功稀释新失败,(b) UCB 探索项
`c·sqrt(ln N/(n+1))` 被大 `n` 压死 → **陈旧的判断被永久锁住**。
"持续校准"必须跟踪**当前胜任度**,不是历史平均。检测延迟随遗忘速率**单调**。

**另一个反直觉结果**:`rr_persist=False`(每次清零)检测**最快**(6 次启动 = 下限),
比 `hl=20` 的 31 次还快。原因:持久化带着前三个 regime 的正面先验,必须先把它忘掉,
而清零从零开始。**对"检测一个变化"而言,清零击败携带。**
代价是放弃了跨任务迁移 —— 这台试验台无法测出迁移的收益(故障是后加的,不是天然的)。

## 三、两类故障 —— 校准到哪个信号上的判别器

这是本轮最重要的实验。**如果只用 option 自己的达成率做校准,它是错的。**

### 故障类型

- **harm(有害)**:反转 π_o(LEFT↔RIGHT),主动朝反方向走。**真的有害。**
- **inert(惰性)**:硬到期上限压到 1 步。它**达不成自己的子目标**(达成率 0.16),
  但**它执行的那一步仍然是 π_o 的最优步**,对主任务有益。**看着坏,其实无害。**

### 结果

| | harm(有害) | inert(惰性) |
|---|---|---|
| `uniform` 成功率(故障段) | **0.000**(一个回合都成功不了) | 正常 |
| `uniform` 步数(故障段) | nan(全灭) | 11.09 |
| `internal-hl20` | 成功率 **1.000**,检测延迟 21 | 步数 **12.13**(更差),检测 31 |
| `advEX-hl20` | 检测 100,adv 转负 −0.0003 | **未检测**,步数 **11.09**(= uniform 逐位一致) |

**判据分离(`inert` 故障段,`advEX` 臂)**:

    内部达成率  0.158   ← 崩了, 内部判据判它"坏"
    主任务 adv  +0.0412 ← 仍为正, 主任务判据判它"还好"

**两条判据给出**相反**的判断,而正确答案是"还好"** —— 因为它每步仍在推进主任务。
按内部判据淘汰它 → 白损失 π_o 的好步 → 步数 11.09 → 12.13,差 **1.04 步**(3 seed 一致)。

⇒ **校准到错误的信号上,会淘汰有用的东西。主任务信号不是优化,是正确性修正。**

### 势函数质量是个独立的限制(诚实标注)

`rr_pot="learned"`(agent 自己的 Q)在本轮**不可用**:早期 Q 是乐观常数(≈1.0),
`adv ≈ −0.004` 全是噪声 → 阈值 0 → **所有 option 全判坏 → fallback 占比 1.000**,
性能崩(T_adapt 76/100/69 vs 20/27/20)。换成 `rr_pot="exact"`(模型 VI 的 `V_main`)后
健康段 `adv = +0.041/+0.034/+0.042` 正常为正,机制工作。

**即:结构是对的,缺的是在线可用的势函数。** 这是一个真实的未解问题,
不是接线错误 —— 而且它正是"持续自我校准"最终要自己解决的那件事(自己学出可用的
`V`,而不是靠模型)。当前 `learned` / `exact` 的差距就是它的度量。

## 四、事前判据(跑前写死)

两类故障各 **6/6**:

    harm  ① uniform 全灭而校准臂成功     成功率 0.000 -> 1.000
          ② 坏占比下降                   0.8201 -> 0.3830
          ②b 干净势函数下 adv 转负         -0.0003
          ③ 不遗忘更慢                    1201 vs 21
          ④ 不持久化最快                  6 vs 21
          ⑤ 退回基元层更多                0.249 -> 0.806
    inert ① 内部判据淘汰反而更差         11.09 -> 12.13
          ② 主任务判据不开火, 步数一致    11.09 vs 11.09
          ②b 两条判据分离                 内部率 0.158 / adv +0.0412
          ③ 不遗忘更慢                    400 vs 31
          ④ 不持久化最快                  6 vs 31
          ⑤ 退回基元层更多                0.424 -> 0.803

### 判据本身被实测修正三次(值得记)

1. **① 第一次用步数比** —— 有害故障下 `uniform` **一个回合都成功不了**,
   `steps_go = nan`,比较直接崩在 nan 上 ⇒ 改用成功率(总是有限)。
2. **臂子集越界** —— 判据硬引用 `adv-hl20`,而该臂不在本次 `--arms` 里 ⇒ `KeyError`
   ⇒ 所有判据加 `in out` 守卫。
3. **`adv` 阈值 0 在 learned 势函数下太紧** —— 不是判据错,是信号不可用;
   加 `rr_pot` 对照把两个因素分开(这才是正确的诊断动作,不是调阈值)。

## 五、仍然没做(明写)

- **在线势函数**:`learned` 不可用(见 §三)。这是最大的开放问题。
- **迁移的收益无法测**:故障是后加的,不是天然随 regime 变化的。
  要测"持久化带来迁移收益",需要一个**天然共享结构**的链。
- **超参未扫**:`rr_min_launches` / `rr_calib_min_rate` / `rr_ucb_c` /
  `rr_calib_min_adv` 四个都是固定值。
- **只在 KeyDoor 上验证**;未接进 lm4/lm5 管线。
- **`eff` 分数**(每步产出多少达成)加了但还没单独扫。

---

## 六、一句话总结

**"持续"= 遗忘 + 持久化 + 校准到主任务信号上。三者缺一不可,而缺的那一个
(主任务信号)会让校准主动淘汰有用的东西 —— 它比"没有校准"更糟。**
