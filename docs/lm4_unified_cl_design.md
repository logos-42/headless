# LM 系列统一持续学习框架 — 设计

> 目标: **一个 SSM backbone,跨模态持续学习**(文本 → 组合规则/推理 → 物理测量),
> 把 lm1/lm2/lm3/lm4 的四套数据管线与全部 CL 机制收进同一框架。

## 一、为什么是这个方向(而不是"把 lm4 做成通用模型")

现有体量决定了"专用 vs 通用"不是设计选择, 而是容量问题:

| 模型 | 参数量 |
|:--|--:|
| lm4 WaveSSM | **213 K** |
| lm2 / lm3 (RLN, 不含 embedding) | **0.67 M** |

行业经验值: 连贯文本 ≈ 100 M; 基础语言理解 ≈ 110 M; 简单推理 ≈ 1 B。
即现有系列要涨 **50×–500×** 才谈得上"语言/推理能力"。

**所以正确的做法是反过来: 让 CL 架构本身成为贡献, 并让它跨模态运行。**
跨模态(语言 ≠ 逻辑 ≠ 等离子体测量)比 Split-CIFAR 难得多 —— 那才是真正的分布漂移。

## 二、四套资产的现状盘点

| 资产 | 内容 | 可复用的部分 |
|:--|:--|:--|
| **lm1** | 排列规则世界 (S4 合成规则) + `S4ValueProposer` 自动提议 + `V35_Learner_A` 的 `adapt_graph` | **推理试验台**(规则程序有 ground truth, unseen 结构分桶 c3/c4/dbl) |
| **lm2** | char 级文本, 域 A/B/C | 文本 CL 的最简管线 |
| **lm3** | BPE 文本, 域 en/zh/code, `method ∈ {base,replay,oml,combo,oml2}` | **CL 方法扫描的参照实现** |
| **lm4** | RBSP-A 电磁波 → 密度域分类, 6 域, WFR 波谱 | 真实非平稳测量; 探针式天花板归因 |

关键修正: **lm1 测的不是自然语言, 是组合规则**; 测语言的是 lm2/lm3。
这个区分要在论文里写清楚 —— 它恰好让"推理"那一支站得住。

## 三、要聚合的 CL 机制清单(lm4 应全量接入)

| 机制 | 来源 | 现状 |
|:--|:--|:--|
| Replay (按域均衡 + 比例可调) | lm4 已有 | ✅ 已验证 (0.6144±0.0186, CV 3.0%) |
| 域顺序 (密度递增课程) | lm4 Q4 | ✅ 有效 (+0.054 replay, −0.063 遗忘) |
| **OML 快慢双循环** | lm3 `oml` | ✅ 已移植 (`--cl-method oml`) |
| **OML 真双循环 (support/query)** | lm3 `oml2` | ✅ 已移植 (`--cl-method oml2`) |
| **PLN per-feature 步长 (Meta-SGD)** | lm1 `V31_PLN` | ✅ 已移植 (`hibs_lnn/pln_head.py`) |
| **Reptile init 平均** | lm1 `V31.2 meta_step` | ✅ 已移植 (`--reptile-lr`) |

## 四、目标架构

```
                     ┌─────────────── 共享 meta 参数 θ ───────────────┐
  输入(按域)          │                                                │
  ┌─ 文本 tokens ─┐   │   RLN: Embedding/in_proj → SSM × n_layers       │
  ├─ 规则 tokens ─┤──▶│        (复值对角选择性 SSM, 213K→100M 可扩)      │
  └─ 波形特征  ──┘   │                     ↓                          │
                     │   PLN/SwiftTD 头: 小 MLP + per-feature 步长 β    │
                     │                     ↓                          │
                     │   内循环: support 上适应 K 步 (快, 只动头)       │
                     │   外循环: query loss 反传 θ (慢) + Reptile 平均  │
                     └────────────────────────────────────────────────┘
                                         ↑
                              Replay buffer (跨模态, 按域均衡)
```

**域序列(持续学习流)**: `en/zh/code 文本` → `规则世界(推理)` → `物理状态(电磁波)`

每一段结束时评估**全部已见域** → 得到跨模态遗忘矩阵。

## 五、评估协议(必须冻结、可审计)

1. **多 seed**: 每配置 ≥5 seed, 报 mean ± std 与 CV(单 seed 结论不可信)
2. **三路对照**: naive(灾难性遗忘基线) / replay(简单强基线) / OML 双循环
3. **天花板**: 每域都要有 joint 上限, 保留率 = replay_acc / joint_acc
4. **消融**: 逐个去掉 per-feature 步长 / Reptile / 裁剪 / OML, 证明每一项的边际贡献
5. **跨模态迁移**: 训完文本后, 规则域与物理域的 cold-start 是否更快(正向迁移)?

## 六、扩容路线

| 阶段 | backbone | 目的 |
|:--|:--|:--|
| P0 | 213 K (现状) | 机制验证: OML 双循环是否值得(进行中) |
| P1 | ~10 M | 文本域开始能生成连贯片段; 验证 SSM 扩参是否近线性收益 |
| P2 | ~100 M | 文本域真正有语言能力(可主张); 三模态统一跑通 |
| P3 | ~1 B | 推理域进入可讨论区间(2×A100-40GB 上限附近) |

## 七、诚实的风险

1. **OML 双循环目前没跑赢简单 replay**(60 步小测仍差; 正式规模 4 个配置在跑)。
   如果它最终还是没赢, 那本身就是有价值的负结果 —— **但要有消融证据说明为什么**。
2. **跨模态 CL 可能比单模态更难**: 语言到物理的分布差异极大, 遗忘可能无法用 replay 抑制。
   这正是要测的东西。
3. **"智能"这个词要慎用**。可主张的是: *在明确的、可验证的任务上, 跨模态持续学习不灾难性遗忘*。
   不可主张的是"通用智能"。
4. **评估泄漏是本项目已经踩过的坑**(滑窗重叠 87.5% + 随机切分曾虚增 replay)。
   任何自动化/自改进循环都必须挂在这个已审计的评估之后。
