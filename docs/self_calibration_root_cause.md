# 根源:「持续自我校准」为什么现在不成立

**日期**: 2026-09-27
**问题** (leo): 「我要的是模型以后持续自我校准, 犯错是可以原谅的, 目前的根源在哪, 我没看明白」

---

## 一句话

**整个栈只有一层会因为「自己错了」而改变自己。**

所以现在它不是「持续自我校准」, 是**「被重新生成」** —— 库由统计量重建、π_o 由
假设模型算出、子目标由人指定。犯了错停留在那些层里, 不会回流, 也就无所谓原谅。

---

## 一、每一层「错了会怎样」(代码核实, 非推断)

| 层 | 是什么 | 错了谁来改 |
|---|---|---|
| 基元 Q 表 | `Q(s,a)` | **TD 误差, 每一步** ← 唯一有校准回路的一层 |
| option π_o | 动作策略 | `env.T` 上跑 value iteration —— 假设真模型, 一次算完冻住 |
| option β_o | 终止规则 | 按规则触发; 规则错了 → 一律 `expired`, 无人知晓 |
| option 价值 | `visits/success` | 全仓**唯一**更新点在 `skill_agent.py:240`(旧 `macro` 路径); rr 路径从不结算 |
| 技能库 | 哪些 option 存在 | `maybe_discover` = 定时重建(从静态统计量), 不是修正 |
| 子目标 | 追什么子成就 | 手工指定 / 瓶颈检测器 —— 无经验反馈 |

代码证据(grep 全仓):

    option 层 TD / 价值学习             → 0 个命中
    prune / remove / drop / 淘汰(option 相关) → 0 个命中
    `_rr_settle(self, st, steps, reason)` → 收下 `st` 然后**完全忽略它**

最后一行是最直接的:**option 对象被交到负责记账的函数手里, 然后被丢掉。**

---

## 二、最锋利的证据:L2 的 56/57

L2 那批: option 启动 **57 次**, **56 次 `expired`**, **1 次 `goal_reached`**。

> 整整一批实验, option 层从来没有达成过目标。
> 而系统里**没有任何东西会因为这个事实而改变**。

要发现它需要: 人写诊断脚本 + 事前写死判据 + 跑全量消融。
一个能自我校准的系统应该自己喊出来: 「我的 option 连续 56 次没达成目标」。

**这在结构上等同于: 错了, 但没留痕。**
没留痕的错谈不上「是不是可以原谅」—— 它根本不在学习回路里。

---

## 三、即使给了信号, 方向也是反的

本轮在线矩阵: `rr-exact`(z 用 `V_main`) **9.4 步** vs `rr-zeroV`(z 不用)**9.0 步**。

同一个价值信号, 被接到了 **β_o(什么时候停)**, 而不是
**「这个 option 值不值得留」**。信号一到 → option 提前停 → 控制权交还给
还没学会的基元层 ⇒ 更差。

**用价值去终止, 而不是用价值去纠正。**

---

## 四、唯一的校准雏形, 曾被我亲手关掉

`rr_select_rule` 有一条 `"gain"`: `argmax(子任务价值 − V_main)` 且要求增益 > 0。
它的两重含义: (a) 按估计值排序 = **校准**; (b) 不到 0 就不选 = **淘汰**。

上一轮为让消融可归因, 默认改成了 `uniform` —— 因为负对照臂(瓶颈, c=−1)在
`gain` 规则下永远不被选中, 臂变成**空的**而不是「更差」的。

**为了测量干净, 把被测量的那个机制关了。**

这不是错误(消融必须这样), 但它暴露了设计里缺一条轴:

    轴 A (已做): 固定库, 比不同库的「内容」        → 「有没有用」
    轴 B (缺):   固定库, 比「选择规则」uniform vs 校准 → 「会不会自己学会不用差的」

**轴 B 才是「持续自我校准」的直接测量。** 本轮把它补上了(见下)。

---

## 五、benchmark 把「怎么知道自己错了」免费送给了 agent

`skill_agent.py:322-325`:

    mdp.set_regime(...)                                      ← harness 换世界
    if mode != "primitive": agent.maybe_discover(force=True)  ← agent 被明确告知「世界变了」

`T_adapt` 的钟从切换那一刻起算。所以现在测的是
**「既然告诉你世界变了, 你多久恢复」**;
而「持续自我校准」的第一问是 **「你怎么知道自己错了」** —— 这一半从未进过 benchmark。

---

## 六、本轮补的那一格: 最小自我校准闭环

改动(`hibs_lnn/rr_agent.py`, 全部**加性**, 默认行为不变):

1. **按 option 归属的台账** `rr_outcome`: 每次结算记到**这个** option 头上
   (`_rr_settle` 里的 `st` 从此不再被忽略)
2. **自诊断** `rr_broken()`: 启动 ≥ `rr_min_launches` 且达成率 < `rr_calib_min_rate`
   → 自己点名「这个 option 的终止机制坏了」
3. **校准选择** `rr_select_rule="calibrated"`: 只用**自己的实测达成率**排序(UCB1),
   **不引入任何外部先验**; 被判坏的排除; 若可启动的**全坏了 → 退回基元层**

信号取 **option 自己的达成率**(`beta_at_feature`), 不取主奖励 ——
KeyDoor 奖励稀疏(只在终点 +1), 拿主奖励做 option 级信号会退化成「所有 option 都得 0」。

### 判据(事前写死, `tests/test_self_calib.py` — **7/7 通过**)

坏 option 制造器: 把它的硬到期上限压到 1 步 → β_o 永远来不及触发 → 每次 `expired`
(**即 L2 的病**)。

| 规则 | 第一块占比 | 最后一块占比 | 比值 | 系统点名 |
|---|---|---|---|---|
| `uniform` | 0.8248 | 0.8423 | **1.021** | — |
| `calibrated` | 0.1071 | **0.0148** | **0.138** | ✓ |

    PASS ① 制造器有效 (uniform 臂坏 option 达成率)  n=1928 reached=400 rate=0.207
    PASS ② uniform 下不衰减 (错误持续)              0.8248 -> 0.8423
    PASS ③ calibrated 自己点名坏 option             broken = ['rr[door]']
    PASS ④ calibrated 下使用占比衰减                0.1071 -> 0.0148 (0.138)
    PASS ⑤ calibrated 主任务不更差                  0.840 -> 0.970
    PASS ⑥ 无坏 option 时不误杀                     broken 数 = 0
    PASS ⑦ 退回基元层次数上升 (校准的唯一手段)       620/1741 -> 1930/2136

### 判据本身被实测修正过两次(值得记)

- **① 第一次打错了臂**: 在 `calibrated` 臂上测「制造器是否有效」——
  而那一臂恰恰把坏 option 避开了。测的是「校准有没有生效」, 不是「制造器有没有生效」。
- **`reached == 0` 判据连 L2 真案都抓不到**: L2 是 1/57 = **0.018**, 不是 0。
  绝对零判据会放过它。改成 `< 0.5`, 依据是实测的两个簇之间的空档:
  `坏的 0.018 / 0.207 / 0.250` vs `好的 0.595 / 1.000`。

### 结构性发现: 校准的作用范围受 `initiation_ok` 限制

坏 option 在 8 个状态上是**唯一**可启动的(32 个状态: 两者都可 8 / 只能 key 8 /
只能 door 8 / 都不能 8)。规则再聪明也**无从避开** —— 不是选择规则错了,
是候选集被 initiation 条件限制死了。

**所以校准唯一能做的事是: 不用它, 退回基元层。** 判据 ⑦ 测的就是这件事。

---

## 七、结论(排序)

1. **校准只存在于一层。** 四个硬编码层围着一个会学习的层。犯的错停在那些层里, 不回流。
2. **信号接错了方向。** 有信号的地方用来「终止」, 不是「纠正」。
3. **唯一的淘汰机制默认关闭, 且从未被单独测量。** 现在它是一条独立的消融轴。
4. **benchmark 免费送了「检测到出错」这一步。**

这四条合起来解释了为什么「option 没用」这个结论反复出现:
在一个只有基元层会校准的系统里, 任何加在上面的、不会校准的层,
只会增加噪声与延迟。`primitive` 每次都是最强臂(1.82x、steps-to-goal 最好)——
不是因为它简单, 是因为**它是唯一会被经验修正的那一层**。

## 八、仍未做(明写)

- 校准信号只用了「option 自己的达成率」。**主任务的信号还没接进来**
  (稀疏奖励下需要势函数或 SMDP 回报, 不是本项目当前的设计)。
- 校准是**在线单趟**的, 没有跨 regime 的持久化(重建库会丢 `rr_outcome`)。
- 只在 KeyDoor 上验证过; 未接进 lm4/lm5 管线。
- `rr_min_launches=6` / `rr_calib_min_rate=0.5` / `rr_ucb_c=1.0` 是三个**未扫**的超参。
