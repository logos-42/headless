# 骨干替换 · 最终裁决 (2026-09-14)

> 起因: leo 指示"换更高效的, SSM 可以去掉"。结论: **完全正确**。

## 一、总结论

**StatMLP(窗口统计 + MLP + 冻结归一化) 在四个轴上全面优于复值 SSM:**

| 指标 | SSM (旧) | **StatMLP + fixed** | 对比 |
|:--|--:|--:|:--|
| **joint 天花板** (6 域) | 0.7213 | **0.8104** | **+0.089** |
| **replay** (6 域, 8/9 seed) | 0.5852 ± 0.0621 | **0.7297 ± 0.0041** | **+0.145** |
| **seed 波动 CV** | 10.6% | **0.6%** | **小 15 倍** |
| **单 run 耗时** | ~13 min | **~0.7 min** | **快 ~19 倍** |
| **学习效率** | — | 90% 达标仅需 **100–200 步** | 预算 1000 步 |

并且**三个粒度全部追平可达上限**:

| 域数 | StatMLP+BN | MLP 可达上限 | SSM |
|--:|--:|--:|--:|
| 3 | 0.9151 | 0.9159 | 0.8510 |
| 6 | 0.8104 | 0.8065 | 0.7213 |
| 12 | 0.6579 | 0.6638 | 0.3674 |

## 二、走过的三个弯路(每个都有教训)

### 弯路 1: 想"修" SSM —— stat-input 只补回 0.011

把窗口统计拼到 SSM **每个时刻的输入**上(0.8510 → 0.8617), 离可达上限 0.9159 仍差 0.054。
**信息不是"没送到", 是递归本身在丢。** → 修不如换。

### 弯路 2: 忘了归一化 —— 值 0.15

StatMLP 初期只有 0.6558(6 域), 探针却是 0.8065。
差别就是探针里那句 `(x-mu)/sd`。**探针的预处理必须原样搬到 backbone。**
补上后 0.6558 → 0.8104(6 域) / 0.4531 → 0.6579(12 域)。

### 弯路 3: BatchNorm 漂移 —— 值 0.47, 而且被我误判成"架构权衡"

加了 BatchNorm 后 replay 只有 0.25, 我一度得出"天花板 vs 保留率存在权衡"的结论,
并做了容量扫描(h32–h512)。**连 h32 都只有 0.27** —— 那时应该继续追问"那是什么",
而不是停在"不是容量"。

**真因: BatchNorm 的 running statistics 随域更新, 旧域数据被当前域统计量归一化 → 特征整体扭曲。**

| 归一化 | replay | 遗忘 |
|:--|--:|--:|
| batchnorm(漂移) | 0.2617 | 0.3329 |
| **fixed(冻结全局 μ/σ)** | **0.7308** | **0.2034** |
| none | 0.1674 | 0.7473 |

**教训: 排除一个假说后必须继续找真因。** "不是容量"不等于"没有原因"。

## 三、方法要点(可复现)

```bash
python3 tests/run_lm4_wave.py \
  --backbone mlp --norm fixed --head linear \
  --cl-method replay --replay-ratio 2.0 \
  --epochs-per-domain 1000 --pool cat --agg-path \
  --wfr-bands 13 --domains 6 --device cuda
```

- **`--norm fixed` 是关键**: 用训练集一次性 μ/σ 填 BN 的 running stats, 并在
  `train()` 里强制 `eval()`, 保证统计量永不漂移。BN 只在作对照时用 batchnorm。
- 归一化是一等公民, 不是实现细节。
