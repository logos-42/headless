# LM5 多模态 · 骨干对照最终裁决 (2026-09-14)

> 起因: leo 指示"把 lm5 切到新骨干"。结论: **只在电磁波上成立, 整体反而变差。**
> 这件事本身有科学价值 —— 它证明骨干选择是**模态依赖**的。

## 二、三个硬结论

### ① 骨干选择是"模态依赖"的 (本轮最有价值发现)

| 数据类型 | 赢家 | 证据 |
|:--|:--|:--|
| 连续信号 + 丰富统计量 (电磁波) | **统计 MLP** | lm4: **+0.145** (8 seed, CV 0.6%); lm5 wave: **+0.065** |
| 离散序列 (文本) | **SSM** | en **+0.125**, code **+0.125** |
| 结构/因果任务 | **无差别** | 四个指标差 ≤0.005 |

**同一套数据上, 换模态就换赢家。** "哪个骨干更好"没有全局答案。

### ② 因果域是"任务瓶颈"不是"架构瓶颈"

逐 seed 几乎完全相同的数字:
```
s42: causal_bal  0.279 (MLP) vs 0.280 (SSM)
s1 :             0.294        vs 0.298
s7 :             0.239        vs 0.239
causal_do_bal:  0.337/0.337, 0.319/0.321, 0.248/0.248
```
两个结构完全不同的架构撞上**同一堵墙** -> 墙在数据/任务里, 不在模型里。

### ③ 平均池化 + MLP 做下一个 token 预测, 方向就是错的

把文本任务改成"池化上下文 -> 预测末位 token"是为了与 SSM 可比,
但**丢掉的正是这个任务需要的词序信息**。结果:
  MLP 文本域 CV 70-141% (不可信)
  SSM 文本域 CV 28-41% (勉强可信)
**这正是 SSM 存在的理由 —— 只是它在电磁波上确实没用。**

## 三、被推翻的自身判断

| 曾判断 | 现状 |
|:--|:--|
| "把 lm5 切到新骨干" | 只在 wave 上成立; 整体反而变差 (0.2876 vs 0.3117) |
| "文本任务改成池化预测末位 token" | **错** —— 丢掉了任务必需的词序信息 |

## 四、建议: lm5 改为混合骨干

```
文本 (en/zh/code)  ->  SSM 序列主干     (需要词序)
电磁波 (wave)      ->  统计 MLP         (需要全局统计量)
因果 (causal)      ->  两者皆可         (任务瓶颈, 省算力选 MLP)
```

组件已解耦 (`--backbone` 已参数化), 改成按模态分派即可。

## 五、方法学补充

- 2000 步 (10×) 把 wave 从 0.346 拉到 **0.5256 (CV 6.7%)** —— 步数是主要瓶颈之一。
- 排除的分词器混淆: 三个 seed 的 BPE md5 完全相同, 编码缓存也相同
  (`bpe_lm5_{seed}.json` 按 seed 命名但内容一致) -> 文本域的高方差是**真实模型随机性**。
